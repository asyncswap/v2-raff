# Huff matching gas

## Direct claim transfers and bounded batch settlement

The approved settlement path uses direct ERC-6909 claim transfers in Solidity and Huff.
Eight matches now use **956,185 receipt gas in Huff**, versus **1,394,556 in Solidity**
in the repeated-recipient fixture: 31.4% lower. This reaches the one-million target in
that workload and saves another 22.3% relative to the preceding Huff version.

| Matches | Huff | Solidity |
| ---: | ---: | ---: |
| 1 | 352,695 | 468,461 |
| 2 | 430,525 | 565,649 |
| 4 | 594,601 | 832,049 |
| 8 | 956,185 | 1,394,556 |

With a distinct recipient for each order, eight matches cost **1,336,745 in Huff** and
**1,706,643 in Solidity**. Creating more claim balances costs more gas; the sub-million
result is not a universal ceiling. Both fixtures retain the 128 noncrossing blockers.
All revised receipt events match exactly between Solidity and Huff at 1/2/4/8 matches
in both workloads. Older burn/mint events intentionally differ; the comparison tool's
`--allow-prior-event-changes` flag permits only that historical difference and still
requires exact current Solidity/Huff event equality.

Matching combines credits by recipient and currency and flushes them in first-credit
order before returning. Eight pairs produce at most 32 maker credit keys plus one shared
FeeVault key. Both implementations enforce a 33-credit capacity. Self-credits transfer
immediately rather than accumulating. Each order still emits its own fee/match notices;
claim transfers follow the bounded loop. Claim transfers leave unlock deltas unchanged.
Redemption, underlying token payouts, matching priority, and rounding are unchanged.
Any failed transfer reverts order reductions and all earlier credits atomically.

All 30 gross benchmark cases are cheaper in Huff: 0/1/16/128 blockers with repeated
recipients, plus 128 blockers with distinct recipients, each at 1/2/4/8/16/32 matches.
The larger counts compose calls; each hook call still allows at most eight matches.
The repeated-recipient eight-match gross fixture uses 1,206,448 gas and is guarded below
1,225,000. Solidity retains 43,690 optimizer runs; native Huff uses hnc 1.6.2.
Huff hook runtime is 22,168 bytes; Solidity AsyncMatching is 24,158 bytes, both below EIP-170.
The upstream PoolManager compiled as a local test fixture exceeds EIP-170 at these optimizer
settings; protocol module sizes are checked separately, without changing vendor code or settings.

Validation: 867 local Solidity tests, 250 current Huff tests, and 48 Python model/tool tests pass.
Shared campaigns cover 514 operations, 128 matches, 8,109 order-state checks, and 8,109 wallet
checks. New tests check credit aggregation, 33-credit capacity, repeated self-credits, and rollback
of earlier claim credits on a later transfer failure. Lean generation and focused refinements
build; the generator leaves shared-memory credit mutation opaque. Arithmetic conservation and
capacity lemmas do not establish a full batch-memory refinement proof. Historical Huff storage
fixtures under test/formal remain excluded.

## Prior compact exact ratios and logical deletion

The prior event-preserving matcher uses **1,230,868 receipt gas for eight matches**,
12.7% below the packed-sequence version and 24.5% below Solidity in the same fixture.
This version does **not** meet the one-million target.

| Matches | Prior Huff | Current Huff | Solidity |
| ---: | ---: | ---: | ---: |
| 1 | 407,929 | 375,854 | 490,024 |
| 2 | 520,133 | 489,616 | 626,378 |
| 4 | 810,050 | 725,556 | 943,316 |
| 8 | 1,410,079 | 1,230,868 | 1,631,254 |

Exact bounds pack positive numerator and denominator into one word when both fit
uint128. Larger values use an explicit marker and two full-width words; comparisons
remain exact. Deletion clears the amountIn liveness marker. Other fields are retained
and overwritten on recreation, while all public views return canonical zeros for
deleted orders. Signed repricing and native-output prechecks also gate retained fields.
Raw storage therefore retains deleted values; this does not provide data erasure.
The bound layout changes and requires a fresh instance. Runtime is 21,688 bytes.

Full-width round trips and wide/compact/wide reuse pass 1,024 fuzz cases. A dedicated
regression checks every deleted-order getter and identical-ID recreation. The current
suite has 249 passing tests; historical test/formal storage fixtures remain excluded.
Python traces pass against both contracts, and all compared receipt events remain
identical at 1/2/4/8 matches. The eight-match gross benchmark is guarded below 1,500,000.

The same receipt fixture now saves another 72,345 gas (4.9%) for eight matches.
Creation and queue sequences occupy separate 64-bit fields in one order-storage word.
Repricing changes only the queue field; maker age and signature incarnation checks read
only the creation field. Full fills settle the entire bid directly and skip residual
minimum and proportional-fee arithmetic. Partial-fill rounding and dust handling are unchanged.
This changes the internal storage layout and requires a fresh instance; it is not an
in-place migration of existing order storage. The hook runtime is 21,301 bytes.

All receipt events remain identical to both prior Huff and Solidity at 1/2/4/8 matches.
The 245 current Huff tests and regenerated Python comparisons against both contracts pass.
The 24-case gross matrix was rerun; the eight-match, 128-blocker case uses 1,782,683 gross
gas, guarded in CI below 1,800,000 for this fixture. Native code still uses hnc 1.6.2 and
the Solidity harness retains 43,690 optimizer runs. Gas remains workload-dependent.

## Changes

- Pack eight released 32-bit radix-node IDs into each storage word. Popping changes the logical
  length; inactive lanes remain unreachable and are overwritten on reuse. Retained node records
  are fully initialized when allocated again. The allocator remains bounded by peak live nodes.
- Cache exact numerator/denominator extrema instead of order IDs. Repair stops when the stored
  ratio is unchanged. A recycled first insertion branch always propagates to its new ancestors.
  Selection follows one right-first eligibility path at that exact extremum, preserving price,
  priority-bid, and queue-age ordering without linear scans.
- Replace binary tick inversion with the v4 logarithmic method: 14 fractional log bits and an
  exact boundary check. This reduces order-admission and residual-repricing work; full-fill
  matching does not rely on this change for its measured savings.
- Avoid clearing the unused order slot and short-circuit comparison of identical ratio words.

The internal storage representation changes; no public selector or matching rule changes. The
optimized hook runtime is 21,194 bytes, below EIP-170's 24,576-byte limit. The standalone matching
benchmark also uses the packed allocator.

tests and the live-input, payout-callback, claim, fee, and signature regressions. Historical storage-
specific fixtures under test/formal remain excluded and are not current Huff refinement proofs.

Run `forge test --no-match-path 'test/formal/**' --fuzz-seed 0x20261024` here. From uv4, run
`uv run --extra priority-model python examples/validate_three_way.py --solidity /path/to/contracts --huff /path/to/v2-raff`.

check complete receipt-event equality and calculate savings. The importer rejects a fixture whose
stored pool FeeVault differs from the hook's immutable vault. The export harness explicitly loads
that configuration before dumpState so cold configuration slots are retained.

# Huff synchronization validation — 2026-10-24

## Result

The native Huff hook and Router reproduce the covered current Solidity behavior. The current behavioral suite passes **238 tests**, with **0 failures** and **1 RPC-dependent fork skip**. Python passes **43 model tests**. The shared differential run passes **100 matching vectors**, signature/hash vectors, and **8 stateful campaigns** on each implementation. The campaigns contain **514 operations**, **128 matches**, **8,109 order-state checks**, and **8,109 wallet checks**. A further **174 Python-derived tick-key vectors** pass against native Huff, including extreme ratios and both currency orientations.

This is differential evidence for the covered inputs, not a proof of arbitrary bytecode equivalence. No contracts were deployed to a network.

## Synchronized behavior

- Priority-only orders mint input and USDC bid claims at creation; unpaid bids revert the complete PoolManager unlock.
- Per-bucket exact-price summaries select the best exact price before fee and queue-age ties. The summaries are repaired on insertion, removal, repricing, and residual updates.
- Tick keys use both trade direction and numeraire orientation, with the same lower and upper clamps as Solidity.
- Incoming orders and keeper matching share the global, eight-pair bounded loop. Pending input settlement blocks matching only for a live pending order in that pool.
- Immutable creation sequence determines maker execution price. Repricing changes queue sequence while preserving creation sequence.
- Residual minimums scale proportionally with upward rounding. Pool minima close dust residuals into claims; repricing enforces minimum order and bid requirements.
- Matching credits ERC-6909 proceeds and dust refunds. Filler, cancellation, and liquidity-fill paths retain their current payout behavior. State updates precede recipient callbacks.
- Priority fees route to FeeVault. Pool liquidity cannot capture those bids.
- Router fills check the expected live input and re-read input/minimum after payment.
- Signed cancellations share hook nonces and bind immutable creation sequence. Generic TokenClaims burns claims before withdrawal and preserves claims and allowance on failed transfers.

The twelve current Nethermind regression tests pass on native Huff, alongside signature, minimum-order, callback, native-payment, liquidity-fill, claims, and fee-accounting tests. Stateful invariant campaigns exercise submit, cancel, reprice, matching, liquidity fill, withdrawal, and unpaid-bid attempts.

## Gas

The same cold-storage unlock harness measures gross execution gas, excluding refunds and transaction intrinsic gas. Both harnesses use 43,690 Solidity optimizer runs; native Huff is compiled by hnc. The fixture contains 128 noncrossing blockers and 32 matchable pairs, with no LP liquidity.

| Matches | Solidity gross gas | Huff gross gas |
| ---: | ---: | ---: |
| 1 | 571,633 | 671,434 |
| 2 | 775,361 | 948,165 |
| 4 | 1,194,054 | 1,509,268 |
| 8 | 2,054,602 | 2,628,567 |

Huff is currently more expensive on this matching workload. Retaining unreachable radix nodes for full initialization on reuse reduces redundant storage writes, but does not eliminate that gap. These values must not be compared directly with receipt-gas measurements that already include refunds. Bounded work does not imply a low enough fee for every chain.

## Reproduction and limits

Run `forge test --no-match-path 'test/formal/**' --fuzz-seed 0x20261024` in this repository. Run `uv run python examples/validate_three_way.py --solidity /path/to/contracts --huff /path/to/v2-raff` from uv4 to regenerate oracle expectations and execute both implementations. Tool versions: Foundry 1.8.6, hnc 1.6.2, solc 0.8.26.

Historical storage-specific fixtures under `test/formal/` are preserved, compile with the compatibility ABI, and are explicitly excluded from the current behavioral suite. They encode retired FIFO, deferred-escrow, and storage-layout assumptions; they have not been updated into current Huff refinement proofs. Deprecated declarations in compatibility interfaces do not restore the removed runtime selectors. The new Solidity batch convenience contracts have no native Huff equivalents in this change.

Signed repricing now encodes `createdSequence` after `orderId`, consistently with the declared type in Solidity, native Huff, and Python. Regressions reject an unused signature after same-ID recreation, preserve the replacement and unused nonce, and accept a fresh signature. Same-block repricing remains allowed. Signatures made without creation sequence must be signed again. Updated regression logs and source fingerprints are in the Solidity repository at `audit/validation/reprice-incarnation-2026-10-24/`.
